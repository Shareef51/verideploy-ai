# ADR-0033 — Reproducible monorepo build boundary

Status: Accepted

## Decision
VeriDeploy uses one release version across the root Node package, every workspace package, the Python distribution, and the Helm chart. A deterministic integrity manifest fingerprints generated contracts and build-graph configuration. CI validates this manifest before expensive jobs and uses frozen dependency installs when lockfiles are present/generated by the release process.

Workspace ownership is explicit in `config/monorepo/policy.json` and `.github/CODEOWNERS`. Cross-workspace behavior must flow through contracts or declared dependencies, not source-path imports.

## Consequences
A version or generated-contract drift fails CI. Global monorepo policy changes invalidate all incremental CI groups. Clean-clone builds use pinned tool versions and frozen dependency resolution; network availability remains an external prerequisite for a first dependency hydrate.
